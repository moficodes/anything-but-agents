# Client-Side Real-Time Simulation with Explicit World-State Snapshots on Agent Substrate

The 2D Dungeon (`cmd/dungeon2d`) runs all 60fps real-time gameplay—hero movement, enemy A* pathfinding, line-of-sight aggro, projectiles, timed attack cooldowns, traps, item pickups, and floor traversal—entirely in the browser client, and only communicates with the Agent Substrate `Actor` via the Gateway when starting a session, explicitly saving (`Save` button or `Save Shrine`), reverting (`Save-Scum Revert`), or forking (`Timeline Fork`). On each save, the client transmits the complete `World State` (every entity's live position, HP, aggro status, inventory, and unlocked gates/switches across all 8 floors) to the `Actor`, which stores the snapshot in Go heap RAM (`ActorSession`) and suspends to GCS (`kubectl ate suspend`). This prevents real-time combat ticks from saturating the shared 3-replica `WorkerPool` while ensuring that `kubectl ate revert` and `--tag` timeline forks faithfully restore the exact spatial and combat state of the entire dungeon world.
